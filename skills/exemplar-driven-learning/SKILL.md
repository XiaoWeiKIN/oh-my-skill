# Exemplar-Driven Learning

**以代表性案例建立领域知识，以对照研究形成独立判断。**

“学习头部”是一种高效的抽样策略，不是“成功者做过的事都值得照搬”。Skill 负责组织学习与研究过程，不决定用户应该学习哪个领域。

## 核心原则

- **问题先于案例**：先明确想获得的能力，再选择能够回答关键问题的对象。
- **代表性优于知名度**：领先、经典、影响力大可以成为候选理由，但不等于方法正确。
- **覆盖优于数量**：选择能代表不同路线、条件与解释的少数案例，而非简单排名。
- **理解优于模仿**：区分背景、目标、关键机制或论证、代价和失效边界。
- **证据优于权威**：案例中的事实、归因与作者判断分开；注意幸存者偏差。
- **迁移必须检验**：用符合本领域的方法进行复现、练习、批判性解释或方案验证。

## 工作流

### 1. 明确学习目标与领域的知识性质

结合用户的提问与上下文，提炼学习者最终应掌握的判断、技能或解释能力。已知约束直接使用，不强制多轮问答。

先判断本次研究偏向哪一种（可同时适用）：
- **解释性**：理解事件、现象、思想或作品为何形成。
- **因果性**：判断某做法是否导致某结果，识别混杂因素与反例。
- **规范性**：比较价值、原则、目标之间的冲突。
- **实践性**：形成能够用于现实决策、创造或操作的方法。

将宽泛领域转成 3–7 个关键问题。例如“学习城市规划”可以拆成“如何平衡交通效率与步行体验”“不同密度下公共空间如何组织”。**不自动把问题改写为软件架构或商业产品分析。**

### 2. 构建问题地图并筛选案例

先列研究维度，再挑选不同维度上的代表案例。通常深挖 2–4 个，但以覆盖和研究成本决定数量。

逐项审查候选：
1. **代表性**：为何是这个问题的典型或影响深远的案例？“头部”的判断依据是什么？
2. **差异性**：它是否揭示不同学派、技术路线、时代条件或组织方式？
3. **可考察性**：能否获得原始材料、可信研究、实物、公开记录或可复现成果？
4. **可比性**：比较双方是否解决相似问题？是否在不同层次或条件下被误比？
5. **局限性**：有哪些被忽略的失败、未被记录的经验、幸存者偏差或证据空白？

必要时加入反例、边缘案例或失败案例。用户已指定对象时尊重其范围，并明确尚未覆盖的重要维度。参考 [references/research-protocol.md](references/research-protocol.md)。

### 3. 研究案例背后的逻辑

对每个案例建立研究卡：
- **核心问题与目标**：它想解释、创造、解决或证明什么？
- **所处环境**：时间、制度、资源、受众、知识基础等前提是什么？
- **关键过程**：它通过什么机制、推理、方法、制度或表达形式发挥作用？
- **替代路线**：当时有哪些选择或竞争性解释？
- **结果与代价**：哪些成效/影响有证据，哪些只是后来归因？代价是什么？
- **适用边界**：不同条件下是否仍成立？
- **来源与争议**：原始证据、权威研究、不同解释分别是什么？

在技术、商业、艺术、历史、科学等领域调整问题表述，不强制套用“请求路径、源码、吞吐量、性能指标”等技术术语。

### 4. 跨案例对照并提炼条件化结论

按相同问题建立对照矩阵，而非分别写几篇人物/项目百科。重点追问：

- 哪些规律在不同案例中反复出现？有何前提？
- 差异来自目标、环境、资源、价值取向还是证据质量？
- 有没有不能直接比较的层次、时代或尺度？
- 有哪些竞争性解释、遗漏样本和无法确定的因果关系？

把结论写成 **“在条件 A 下，因机制或理由 B，做法 C 可能适用；当条件 D 改变时，应重新评估”**。对规范性/解释性问题，可输出有依据的多种解释，而非强行给唯一的最佳实践。

### 5. 通过领域适配的练习检验学习

选择一个最小任务检验是否理解并能迁移，而不是默认写代码或做工程实验：

| 研究类型 | 适合的验证方式 |
| --- | --- |
| 技术与自然科学 | 复现计算或实验、实现原型、检验反例与边界 |
| 产品与商业 | 场景推演、用户任务测试、决策模拟、可衡量的小试点 |
| 历史与社会科学 | 对照原始史料、检验竞争性解释、识别时空与制度差异 |
| 哲学与理论 | 重构论证、寻找反例、检验概念及前提是否一致 |
| 艺术与设计 | 作品分析、原创练习、同行评议或实际受众反馈 |

可执行实践必须区分 **已执行 / 计划执行 / 无法验证**，不能编造测试结果、历史证据或研究共识。无法直接实验的领域，通过证据交叉检验与论证质量评估，不强行要求可量化验证。

### 6. 交付问题驱动的学习成果

根据请求深度提供：
1. **目标与问题地图**：学习结束能独立判断什么。
2. **案例选择及覆盖范围**：为什么选它们、代表什么路线、遗漏什么。
3. **跨案例比较**：共同问题、各自回答、条件、证据和分歧。
4. **可迁移认识**：一般性原则、条件、反例或竞争解释。
5. **练习与验证**：最小可执行任务、检验标准与未知。
6. **下一步材料**：只推荐能填补当前知识空白的资料。

对“学某领域应该看谁”的简短问题，先给少数代表案例与理由，再建议起步问题，不强制输出长篇研究报告。

通用研究模板与证据要求见 [references/research-protocol.md](references/research-protocol.md)；多学科用法见 [examples/cross-domain-examples.md](examples/cross-domain-examples.md)。

## 与其他 Skill 的边界

- 负责**如何研究与学习**，不是编程、商业、历史或艺术的专属专家 Skill。
- 若需要将研究写成正式文档，可协同 `doc-writing`；需要持久写入 Wiki 时可协同 `llm-wiki-maintainer`。遵守用户的写入范围，不自动修改仓库或笔记。
- 如资料随时间变化，查证版本与时间；来源不可得时说明未核验。
- 不能从“某案例成功”推断“它的方法导致成功”或“任何领域都只需学习几个案例”。

**成功标准：学习者面对未见过的新问题，也能解释不同路线为何成立、何时失效，以及该如何选择。**
