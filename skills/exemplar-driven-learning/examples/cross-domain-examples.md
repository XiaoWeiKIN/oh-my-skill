# Cross-Domain Examples — 跨领域示范

此文件只展示**如何设计学习任务**，并不宣称以下候选案例的具体因果解释已被核实。实际研究必须基于当前可获得的可靠资料与用户需求判断。

## A. 技术：学习 eBPF 的工程实践

用户请求：“研究 eBPF，应当重点看哪些头部项目？”

**学习目标：** 理解 eBPF 程序如何加载与运行，以及如何在实际系统中构建可靠的数据采集能力。

**问题地图：**
- 核心运行模型是什么？Verifier、Hook、BPF Map 如何协作？
- 用户态与内核态的数据交换如何组织？
- 内核版本、权限与可观测性需求如何影响设计？
- 怎样判断一项实现是通用机制还是场景特化？

**候选对象与分工（需当次核对版本）：**
- Linux Kernel BPF 官方文档：学习概念与约束，不是普通“项目案例”。
- `libbpf-bootstrap`：通过小型程序跟踪最短执行路径。
- `cilium/ebpf`：研究一种 Go 用户态交互与装配路径；只是可选的语言实现示例。
- OpenTelemetry eBPF Instrumentation：研究自动埋点在可观测性中的应用。

**实践：** 任选熟悉的用户态技术栈，复现一次安全的事件采集；对比至少一种不同 Hook 或数据交换方案，记录能够证实的边界。不要假定学习 eBPF 必须使用 Go。

## B. 历史：比较不同帝国的治理体系

用户请求：“通过少数典型案例，理解古代大型国家如何维持治理与整合。”

**学习目标：** 区分行政制度、地方权力、交通通信与合法性等维度，形成有证据的比较解释。

**问题地图：**
- 中央权力如何与地方机构协作？
- 组织动员与行政成本之间有何取舍？
- 制度如何适应幅员、技术和社会结构？
- 对某一历史结果的解释是否混入后世评价？

**候选对象：** 秦汉与罗马相关治理实践，但必须先限定比较时期和问题。同为“大帝国”不意味着制度、时间和资料可无条件对齐。

**练习：** 选择一条具体制度，对照相关一手史料与至少两种学术解释；明确相同、不同与证据缺口。不能直接把历史结果当作可重复的工程实验。

## C. 设计：学习优秀信息图的表达方法

用户请求：“想学习高质量解释型信息图，研究哪些代表案例？”

**学习目标：** 能够独立决定信息层级、图文比例、视觉引导与受众理解负担。

**问题地图：**
- 作品如何决定读者先看到什么、再看到什么？
- 图示帮助表达了什么关系？有没有制造误导？
- 视觉风格与阅读场景之间有什么联系？
- 哪些设计原则可以迁移，哪些依赖特定媒介？

**候选对象：** `The Economist`、`The New York Times` 的可视化作品，以及与其表达路线显著不同的教育类信息设计作品。选择具体作品后再做实证分析，不能单靠机构名判断方法优劣。

**练习：** 选一个相同信息主题，制作两种原创表达方案，用事先定义的理解问题收集读者反馈；不复制受版权保护的设计图像。

## 不该得出的结论

- “某系统采用 X，所以 X 必定最优。”
- “某历史政权成功，所以其制度适用于现代组织。”
- “某流行视觉风格获得传播，所以可证明其信息表达更准确。”

更可迁移的结论应明确**条件、证据、反例和替代解释**。
