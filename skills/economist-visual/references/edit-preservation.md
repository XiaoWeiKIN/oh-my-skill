# Preserve & Improve｜基于参考图的保留式优化

## 问题

「更简洁」不是默认更好。改图时保护已有效的编辑表现力，避免把有节奏的柱状图换成平淡面积图、删除主题插画或无理由改变用户喜欢的视觉结构。

## 生成前先写内部 Visual Preservation Contract

```yaml
keep:
  - "主图型：逐年红色柱状图"
  - "大字号衬线标题"
  - "红色增长强调"
  - "汽车与充电桩（主题识别作用）"
repair:
  - "汽车遮挡后四年的柱体和年份"
  - "统计口径和年份来源需验证"
  - "减少冗余的底部指标，扩大图表区"
forbid_new:
  - "未经批准的来源/数字/页码"
  - "凭空增加预测或国家份额"
allowed_transform:
  - "将汽车移至图表右下方独立安全区"
locked_chart_type: "bar"
```

`keep` 作为正向约束写进 prompt，`repair` 作为局部修改任务，`forbid_new` 作为强限制。若用户明确要求整体重做，则解除部分锁定，但仍保留事实边界。

## 改图优先级

1. P0：虚构事实、公式、品牌、来源必须先修复。
2. P1：遮挡、数值比例、错字、可读性问题。
3. P2：视觉平衡、标题节奏、隐喻表达。

P2 美学改动不得破坏已正确的 P0/P1；同等条件下保留用户认可的造型、信息层级、色彩与图表类型。

## A/B 验收

评价至少四个维度：

- 数据/科学是否更准确（不能靠视觉主观评分代替）；
- 读者是否更快理解主要论点；
- 视觉冲击力有没有不必要地退步；
- 用户原先认可的元素是否保留。

对于生成差异明显的两版，不预先宣称「新版一定更好」；记录取舍，必要时让用户选择。
