# macOS 磁盘检查与清理

交付有证据的占用清单或已授权的清理结果。区分目录占用估算、可回收估算和磁盘可用空间净变化。

## 确定范围

从当前对话维护三份简短清单：已授权清理项、明确保留项、尚未确认候选项。记录精确路径及必要的例外；不要将别的会话中的保留目录硬编码成永久规则。

- “检查／再挖掘”只扫描并提出候选；“这几项／前四项都清理”承接最近明确的候选列表，已有授权不重复询问。
- “之前保留的继续不动”持续有效。新的宽泛清理请求不自动撤销保留项；排除保留路径及其包含的数据，避免删除其父目录。
- 若缺失被引用的清单，先找回会话上下文；仍无法确定时询问具体项目，不猜测删除范围。
- 缓存清理不等于删除聊天记录、媒体、项目数据库、源码或本地模型。停止应用、重启机器、移除虚拟机须在授权范围内。

## 建立基线并逐层定位

先检查系统和同一数据卷：`uname -s`、`df -k /System/Volumes/Data`。需要解释 APFS 时用 `diskutil apfs list`，解释 Swap 时用 `sysctl vm.swapusage`。非 macOS 不直接执行本 skill 的平台专用步骤。

先扫描已知大目录的一层，再深入最大项。避免同时扫描整盘、整个用户目录和它们的子目录。并行扫描以 2–3 个为宜；及时输出结果，保留权限错误和超时信息，不能将不完整扫描描述为全盘结论。

可使用只读辅助脚本：

```sh
python3 <skill目录>/scripts/inventory.py "$HOME" --children --timeout 90
python3 <skill目录>/scripts/inventory.py "$HOME/Library/Caches" "$HOME/Downloads"
```

脚本逐项输出 JSON，含数据卷可用字节、`du` 分配空间估算和扫描状态；不删除文件，不跟随作为目标传入的符号链接。超时项目需继续定向细查。候选表给出路径、估算大小、用途、可重建证据和使用状态；不要仅凭名称或时间认定可删。

## 分类核实

- 容器、Docker.raw、Podman、Minikube：读 [references/containers.md](references/containers.md)。
- 开发产物、应用数据、临时文件、日志、Codex 会话：读 [references/files.md](references/files.md)。
- 用元数据定位，避免输出配置密钥、环境变量、聊天内容；识别进程时只展示必要的 PID、工作目录、服务或程序名。

## 执行已授权清理

操作前重新检查目标类型、实际路径、大小、引用情况和保留项。使用精确路径，不递归跟随链接，不根据一个目录名进行全盘通配删除。优先使用应用或平台支持的清理命令；不绕过平台的“仍在使用”拒绝。

按小批次执行并记录成功、失败和跳过项。长操作返回后台会话后继续监控；不能因为等待超时就认为失败或重跑删除。只停止授权范围内的程序，并核验进程身份。保留可恢复依赖的锁文件和源码。

## 核验与汇报

在清理前后读取同一文件系统的可用空间，复查目标和保留数据；必要时稍候再测一次。报告：已处理项目、目录估算、可用空间前后值与净变化、失败或跳过项。

- GiB 按 1024³ 字节，GB 按 1000³ 字节，不混用。
- APFS 克隆、硬链接、稀疏文件使 `du` 和文件逻辑大小不等于可释放空间；嵌套目录不可重复相加。
- 并发下载、日志和系统回收会影响净变化，不把全部变化归因于本次删除。
- 删除仍打开的文件通常不会立即释放；先定位持有进程，不能擅自停止应用。
- Swap 由 macOS 管理，不手动删除。解释使用量；用户授权重启后才能执行重启。

完成后保持简洁，清楚说明实际释放情况和仍需用户决定的项目，不反复推荐已要求保留的目录。
