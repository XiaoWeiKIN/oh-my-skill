# 文件类清理判据

## 开发依赖和产物

`node_modules`、Go 编译缓存、包管理器下载缓存通常可重建，但需区分依赖目录与运行中的应用依赖，并保留锁文件。模块缓存、SDK、全局工具链可能涉及离线工作和重下载成本，作为独立候选展示。

`build`、`target`、`dist` 只是名字。定位最近的 Git 仓库，检查 `git ls-files` 中是否有目标下的已跟踪文件、`git check-ignore` 的规则，以及目录内容与构建配置。已忽略不等于可删，仍需确认不是数据库或交付成品。非 Git 项目依据构建配置和内容判断；证据不足时跳过。检查运行中的 jar、进程工作目录和文件句柄，保留仍在使用的产物。

不要删除 `.git`、未提交源码或用普通 rm 清理托管 worktree；Codex 托管 worktree 使用应用提供的归档能力，确认所需忽略文件已保留。

## 应用缓存、更新包和重复备份

区分 Cache／Code Cache／下载的安装包与配置、登录态、IndexedDB、聊天数据库和媒体。不递归删除整个 Application Support 或应用容器。媒体是用户数据，不能承诺可重新下载。

旧更新包需对比已安装版本、更新时间和打开状态；VS Code 旧扩展结合 `.obsolete` 和实际安装版本确认，缓存 VSIX 与正在使用的扩展分别处理。

重复备份按相对路径、文件内容哈希和缺失项验证，明确保留哪份。仅相同名称或大小不算重复；硬链接或 APFS 克隆即使内容相同，也未必可回收所见大小。

Chromium 等目录中的 `.code_sign_clone` 可能共享 APFS 块。不要把其 `du` 总和当成保证可释放量；结合版本和使用状态判断，未授权不删除。

## 临时目录

`/private/tmp` 不等于可以全删。它可能含活动 socket、浏览器目录、Git 仓库、唯一脚本、补丁、视频成片、数据库和其他用户的文件。

按精确路径和明确来源识别缓存、临时依赖及构建预览，排除保留项和活动进程引用。年龄只作线索，不单独作为删除依据。不跟随符号链接，不清扫其他用户／系统对象。仅凭 `.js`、`.json` 等扩展名不能判断为产物。

## 日志与“删完又涨”

使用定向 `lsof -nP`、进程工作目录、程序身份定位写入者；没有 lsof 命中并不证明以后不会使用。日志目录总量、各文件增长和进程归属分开说明。

- 不再被打开的旧日志可在授权范围内删除。
- 仍在写的普通日志，在已授权清理日志的范围内可原地截断，保留 inode；实现时用不跟随链接的打开方式，核验普通文件再 ftruncate。不要误删 `.pid` 或把数据库 WAL 当普通日志。
- 用户要求“关闭”后核验具体 PID 对应服务，再正常终止并确认退出；不按宽泛关键词杀进程。若由 supervisor 重启，识别对应启动项后再在授权范围内处理。

## Codex

Codex 日志、缓存、更新包、归档会话和 worktree 的专项检查与清理见 [codex.md](codex.md)。不要把整个 Codex 数据目录当作缓存。
